# Pear 2 — обновление сайта для ПК

Это обновлённый сайт Pear для Vercel + Supabase. Старые таблицы, пользователи, посты и файлы сохраняются, если использовать тот же проект Supabase и не удалять данные вручную. Новый дизайн ориентирован на ПК, но мобильный вид тоже оставлен.

## Если Pear уже работает

1. Сделайте резервную копию старого репозитория и базы перед обновлением. Распакуйте архив и замените в GitHub-репозитории вашего проекта файлы `index.html`, `app.js`, `style.css`, `package.json` и `api/config.js` файлами из этого архива. Существующие переменные окружения и настройки авторизации в Vercel и Supabase менять не нужно, если они уже работают.
2. Дождитесь автоматического деплоя Vercel или сделайте Redeploy, затем обновите страницу сайта. На всякий случай проверьте настройки проекта Vercel: `SUPABASE_URL` — Project URL, `SUPABASE_ANON_KEY` — публичный publishable key или legacy anon key. `service_role` и secret key использовать нельзя.
3. **Не запускайте `schema.sql` снова**, если база уже создана! Это исходный скрипт только для новой пустой базы.
4. Для более быстрого получения обновлений других пользователей необязательно, но желательно включить Supabase Realtime: откройте SQL Editor в существующем проекте Supabase, вставьте содержимое `realtime-optional.sql` и нажмите Run. Скрипт добавляет таблицы в публикацию Realtime, не пересоздавая их. Если таблицы уже добавлены, он пропустит их.
5. Откройте сайт в двух браузерах или на двух аккаунтах и проверьте публикации и лайки. Если изменения видны не сразу, проверьте, что таблицы включены в Database → Publications → supabase_realtime, и что Realtime доступен в проекте.

## Если база ещё не создана

В новом пустом проекте Supabase выполните `schema.sql` **один раз**. Дальше настройте проект на Vercel и OAuth, как описано ниже. При желании после этого выполните `realtime-optional.sql`.

## Что изменилось

- Лайк реагирует сразу и анимируется, запрос сохраняется в Supabase в фоне. Если запрос не удался, лайк откатится и появится уведомление.
- Вкладки и действия работают без полной перезагрузки страницы. Лента сверяет данные в фоне, оставляя неизменённые карточки на месте.
- Новые данные запрашиваются при событии Realtime, если таблицы включены в публикацию. Дополнительно идёт проверка примерно раз в 25 секунд, когда вкладка активна, поэтому сайт работает и без Realtime. Реальная скорость зависит от интернета, загрузки и региона Supabase; мгновенное обновление между устройствами не гарантируется.
- Изображения загружаются по мере прокрутки. Действия, требующие сохранения (например, публикация с файлом), всё равно ждут ответа сервера.
- Первая загрузка по-прежнему зависит от интернета, CDN, работы Vercel, Supabase и объёма данных. Для больших нагрузок нужны серверная пагинация, индексы под поиск и агрегаты. Лента и поиск постов ограничены последними 100 постами; профили и подписки — максимумом выборки API. Тренды — среди загруженных постов.

## OAuth и безопасность

Настройте Supabase Authentication → URL Configuration: Site URL — адрес Vercel, Redirect URLs — точный адрес сайта с `/` в конце. В Authentication → Sign In / Providers включите настроенные провайдеры. В настройках OAuth-приложения GitHub, Google или Discord указывайте Callback URL из Supabase, а не URL Vercel. Секреты провайдеров храните только в Supabase и панели провайдера, не в GitHub. Все кнопки входа отображаются, но будут работать только включённые и настроенные провайдеры.

Файлы постов доступны всем, у кого есть прямая ссылка на них, так как бакет публичный. Поддерживаются JPG, PNG, WebP и GIF до 5 МиБ, не видео. Профили и записи видны авторизованным, а права изменения защищены существующими RLS-политиками. Перед публичным запуском необходимы модерация, ограничения запросов и спама, мониторинг, резервные копии и проверка защиты данных. Личные сообщения и уведомления в этой версии не реализованы.

Для запуска нужны интернет и доступ к CDN esm.sh. Открытие HTML-файла напрямую не заменяет размещение на Vercel: `/api/config` работает как Vercel Function.

Документация: https://supabase.com/docs/guides/realtime/postgres-changes, https://supabase.com/docs/guides/auth/redirect-urls, https://vercel.com/docs/functions.
