# Pear — соцсеть для Vercel + Supabase

Адаптивный проект на JavaScript: вход через Google / Discord / GitHub, реальные пользователи и профили, общая лента, текстовые посты с изображением или GIF, лайки, комментарии, подписки, поиск и удаление своих постов. Данные — в Supabase, файлы — в Supabase Storage. Примеры пользователей или постов не добавляются.

## Запуск

1. Создайте новый проект на https://supabase.com/ и дождитесь его запуска.
2. В Supabase откройте **SQL Editor**, вставьте весь `schema.sql` и выполните один раз. Скрипт рассчитан на пустой проект, не запускайте повторно без очистки или миграции.
3. В Supabase **Project Settings → API** найдите Project URL и публичный anon key (или publishable key, если доступен). Никогда не используйте `service_role`, secret key или пароль базы в браузере и этих переменных.
4. Загрузите содержимое этой папки (включая `api`, `schema.sql`, `index.html`, `app.js`, `style.css` и `package.json`) в корень GitHub-репозитория. Импортируйте репозиторий в Vercel: **Add New → Project**, Framework Preset — **Other**, параметры сборки оставьте пустыми.
5. В настройках проекта Vercel **Settings → Environment Variables** добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY` (публичный ключ из шага 3). Выберите Production и, если нужно, Preview. После изменения переменных сделайте Redeploy.
6. В Supabase **Authentication → URL Configuration** укажите Site URL `https://ваш-домен.vercel.app`. Добавьте `https://ваш-домен.vercel.app/` в Redirect URLs. Для других доменов или preview-деплоев добавьте соответствующие разрешённые URL отдельно. Открывайте приложение по HTTPS.
7. В **Authentication → Sign In / Providers** включите нужные провайдеры и настройте OAuth-клиент каждого в его панели разработчика. В настройках каждого провайдера используйте **Callback URL, показанный в Supabase** (обычно `https://<project-ref>.supabase.co/auth/v1/callback`), а не URL Vercel. Для Google, Discord и GitHub нужны отдельные client ID и client secret; сохраняйте секреты только в Supabase / панели провайдера, не в репозитории. Активируйте только провайдеры, которые настроили: кнопки остальных покажут ошибку, пока они не включены.
8. Откройте URL Vercel и войдите. При первом входе создаётся профиль; ник и описание можно изменить. Создайте пост и проверьте его с другого аккаунта.

Vercel-адрес не появляется автоматически от распаковки архива: проект нужно самостоятельно импортировать и развернуть. Настройка OAuth может зависеть от требований провайдера и его консоли. Вход не заработает, пока не настроены callback URL и хотя бы один провайдер. Если Supabase сообщает о неподходящих URL, проверьте адрес сайта, список redirect URLs и callback в настройках провайдера.

## Возможности и ограничения

- Лента и профили доступны вошедшим пользователям. RLS ограничивает изменение профиля и удаление публикации, лайка, комментария или подписки их владельцем. API использует публичный ключ и токен пользователя; права обеспечивает база, а не скрытие кнопок.
- Изображения хранятся в **публичном** бакете: любой, у кого есть прямая ссылка, сможет открыть файл, даже без входа. Не используйте для приватного контента. Лимит загрузки — 5 МиБ, только JPEG, PNG, WebP и GIF. Видео не поддерживается. При удалении поста его изображение также удаляется; если удаление файла не удалось, проверьте Storage вручную. Удаление аккаунта может оставить файлы в бакете: их нужна отдельная очистка.
- Поиск и тренды обрабатывают не более последних 100 постов; поиск пользователей — до 100 профилей. Это простая первая версия, а не полнотекстовый поиск. Для большого проекта нужны серверная пагинация, поиск и счётчики.
- Не реализованы личные сообщения, уведомления, репосты, модерация, аватары-файлы и подписки в реальном времени. Обновите страницу, чтобы увидеть новые данные других людей.
- Перед публичным запуском нужны правила и модерация контента, жалобы, защита от спама и злоупотреблений, rate limits, резервное копирование, мониторинг, обработка правовых запросов и проверка безопасности. OAuth и политика защиты персональных данных настраиваются владельцем проекта.
- Клиент загружает `@supabase/supabase-js` из esm.sh, поэтому для работы нужен интернет и доступ к CDN.

Документация: https://supabase.com/docs/guides/auth/social-login, https://supabase.com/docs/guides/database/postgres/row-level-security, https://supabase.com/docs/guides/storage/security/access-control, https://vercel.com/docs/functions.
