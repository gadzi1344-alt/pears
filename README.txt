PEAR — обновление профилей, упоминаний и верификации

Это обновление для УЖЕ СУЩЕСТВУЮЩЕГО проекта Pear на Vercel + Supabase. Сделайте резервную копию базы и файлов сайта перед установкой. Старый schema.sql повторно не запускайте — иначе будет ошибка «relation profiles already exists».

1. ОБНОВИТЬ БАЗУ SUPABASE
Откройте Supabase → свой существующий проект → SQL Editor → New query. Откройте файл 1-update-database.sql из архива в Блокноте, скопируйте весь его текст, вставьте в редактор и нажмите Run. Если появилась ошибка — остановитесь и не продолжайте, пока она не исправлена. Скрипт добавляет столбцы профиля, отдельные таблицы прав/галочек и хранилище изображений; он не предназначен для удаления существующих данных.

2. ВЫДАТЬ ПРАВА АДМИНИСТРАТОРА СОБСТВЕННОМУ АККАУНТУ DUROV
Админ привязан к UUID аккаунта, а не к одному лишь нику. Это предотвращает получение прав сменой ника.
- Откройте Supabase → Authentication → Users. Найдите СВОЙ аккаунт по email и скопируйте его User UID / ID. Убедитесь, что именно у этого аккаунта ник durov (в профиле Pear или в Table Editor → profiles). Если ник другой, сначала смените его на durov в профиле Pear.
- Откройте файл 2-make-durov-admin.sql. Замените 00000000-0000-0000-0000-000000000000 ТОЛЬКО в строке `declare admin_id uuid := '...'` на скопированный UUID. Кавычки оставьте. В условии проверки ниже нулевой UUID оставьте без изменений.
- В Supabase SQL Editor создайте новый запрос, вставьте ВЕСЬ изменённый текст и нажмите Run. Скрипт проверит, что этот UUID принадлежит профилю durov, добавит ему права и выдаст галочку. Если UUID не заменён или ник не совпадает, скрипт остановится без назначения прав.
- Никому не отправляйте пароли, service_role, secret key и client secret. UUID — идентификатор аккаунта, не пароль. Права вручную назначает только владелец проекта через SQL Editor. Переименование профиля после назначения не передаёт права другому аккаунту.

3. ОБНОВИТЬ ФАЙЛЫ САЙТА
В GitHub-репозитории сайта замените файлы app.js и style.css в корне на файлы из архива. Создайте папку assets в корне репозитория (если её ещё нет) и загрузите в неё assets/verified.png. Сохраните изменения (Commit changes) и дождитесь деплоя Vercel. Не удаляйте index.html, api/config.js и другие существующие файлы, не меняйте настройки Vercel и Supabase. Затем обновите сайт и при необходимости выйдите и снова войдите.

4. КАК ПОЛЬЗОВАТЬСЯ
- Мой профиль → Редактировать профиль → выберите аватарку и/или баннер → Сохранить. JPG, PNG, WebP или GIF, до 5 МиБ на файл. Изображения доступны всем, у кого есть прямая ссылка; не загружайте приватные данные. Старое изображение удаляется при успешной замене, а при ошибке удаления его может понадобиться удалить вручную из Supabase Storage. При удалении аккаунта отдельные файлы могут остаться в Storage.
- В новом посте начните писать @ для подсказок пользователей или # для тем. Выберите подсказку или допишите вручную. Сохранённые упоминания и хештеги кликабельны. Упоминания НЕ отправляют уведомления; поиск и подсказки ограничены данными, загруженными сайтом (до 100 последних постов и до 1000 профилей, могут действовать ограничения Supabase). После смены ника старое текстовое упоминание может перестать ссылаться на профиль.
- В аккаунте durov нажмите иконку щита в боковом меню. Панель позволяет искать профили и выдавать или убирать галочки. Она не даёт другие модераторские функции. Действия проверяются серверной функцией Supabase; обычный пользователь не может выдать себе галочку только через интерфейс.

Если что-то не заработало, сначала проверьте, что оба SQL-скрипта выполнились без ошибок, в GitHub есть файл assets/verified.png и Vercel завершил деплой. Код проверен с тестовыми данными; после установки обязательно проверьте его с вашим Supabase и вторым аккаунтом. Для публичного запуска нужны независимая проверка безопасности, модерация, защита от спама и резервное копирование.
