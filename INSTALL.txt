PEAR — РЕКОМЕНДАЦИИ, СТАТИСТИКА И УДАЛЕНИЕ АККАУНТА

Что добавлено
- В поиске без запроса показываются до 6 подтверждённых пользователей из загруженных профилей. Это не случайная или персонализированная выдача; список упорядочен по имени. Текущий аккаунт не показывается самому себе.
- В админ-панели: число пользователей, публикаций, новых пользователей за последние 24 часа, верифицированных и приблизительный онлайн. Онлайн — пользователи, активные в видимой вкладке за последние 5 минут. После закрытия вкладки они могут ещё до 5 минут оставаться в счётчике. Одна запись на пользователя, а не на вкладку.
- В редактировании профиля: красная кнопка удаления и отдельное подтверждение словом УДАЛИТЬ. Удаление необратимо и может удалить связанные публикации, комментарии, подписки, лайки и файлы в папках пользователя в двух хранилищах Pear.

Сначала сделайте резервную копию базы и протестируйте всё на тестовом проекте Supabase и отдельном тестовом аккаунте. Не используйте основной аккаунт для теста удаления. Сценарии проверены локально с заглушками, но не проверены на вашем сервере Supabase.

1. База Supabase
Откройте свой проект Supabase → SQL Editor → New query. Откройте файл 4-online-stats.sql, скопируйте его содержимое, вставьте в редактор и нажмите Run. Это обновление для существующей базы после прошлых обновлений, оно не пересоздаёт таблицы сайта. Не запускайте повторно schema.sql и старые обновления. Если есть ошибка, остановитесь и сохраните текст ошибки без секретов.

2. Vercel — секрет для удаления
Откройте Supabase → Project Settings → API Keys. Найдите серверный ключ service_role (в разделе Legacy API keys, если требуется). Никому его не показывайте: это полный доступ к базе. НЕ используйте anon/publishable key вместо него.
Откройте Vercel → проект Pear → Settings → Environment Variables. Добавьте переменную с точным именем SUPABASE_SERVICE_ROLE_KEY и значением service_role; выберите Production и сохраните. Она используется только серверной функцией api/delete-account.js. Не добавляйте секрет в код, GitHub, SQL, чат или переменные с публичным префиксом. Убедитесь, что SUPABASE_URL и SUPABASE_ANON_KEY уже установлены. После изменения переменных нужен новый деплой.

3. GitHub — файлы сайта
Распакуйте архив. В корень репозитория pears загрузите app.js и style.css с заменой старых. В существующую папку api загрузите delete-account.js (путь в GitHub должен быть именно api/delete-account.js). Не удаляйте api/config.js и другие файлы. Сохраните через Commit changes, дождитесь успешного развёртывания Vercel. SQL-файл запускать нужно в Supabase; его загрузка в GitHub необязательна. Файл INSTALL.txt загружать на сайт не нужно.

4. Проверка
- Откройте поиск: отображаются только профили, которым администратор выдал галочку. Если их нет, показывается сообщение.
- Зайдите админом: статистика видна только админам. Данные онлайн обновляются примерно раз в минуту; до первого обновления показания могут быть неполными.
- Создайте ОТДЕЛЬНЫЙ тестовый аккаунт и тестовые изображения; убедитесь в наличии резервной копии. Нажмите Профиль → Редактировать профиль → Удалить аккаунт, проверьте предупреждение и удалите только тестовый аккаунт. Проверьте, что пользователь удалён из Supabase Auth, профиль и публикации удалены, файлы тестового пользователя исчезли из post-media и profile-media, а чужие данные не затронуты.
- При сбое удаления часть файлов уже может быть удалена, даже если аккаунт ещё не удалился. Операция не транзакционная. Если у пользователя есть объекты вне двух папок Pear или внешние зависимости от auth.users, Auth может отказать в удалении; проверьте логи сервера без публикации токенов и секретов.
- После удаления уже выданные JWT могут оставаться действительными до истечения срока. Выход текущей вкладки выполняется; запись новых файлов этим приложением после удаления профиля блокируется новой политикой. Доступы и дополнительные политики проекта необходимо проверить отдельно.
- Уже сохранённые резервные копии и сторонние копии файлов автоматически не удаляются.

Показывая онлайн, учитывайте конфиденциальность и укажите это в правилах сайта. Ключ service_role обходит RLS и должен оставаться только на сервере.
